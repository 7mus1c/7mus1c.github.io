# LLM 原理

目前所有主流大模型的底层协议和核心引擎是完全一致的：

**LLM = Transformer架构 + Attention 机制 + 大规模预训练**

## 神经网络

在神经网络诞生之前有个东西叫 N-gram。它的核心就是靠统计概率。统计所有文本里「说完『今天天气』最常接什么」，一百次里八十次是「很」，那就猜「很」。这就是 **N-gram**。

但是这东西有两个绕不开的问题：

1. 换个没见过的说法就挂了。比如我今天吃了，它没见过，直接就无法回答了。
2. 不长记性，通常只能往回看 2-3 个词，如果再长计算量就爆炸。

所以 N-gram 就被淘汰了。

**接棒发生在 2003 年。** 一位叫 Bengio 的科学家第一次让神经网络来干"猜下一个词"的活，针对它的两个毛病挨个治：

**毛病一：没见过就挂 → 给每个词发一张"性格名片"。**

以前电脑眼里的"猫"，就是词典第 4392 号，一个光秃秃的编号——它不知道猫毛茸茸、会抓老鼠、和狗是近亲。Bengio 的做法是给每个词一串数字（比如 300 个），意思接近的词，数字也接近。相当于给所有词排座位：**猫和狗坐隔壁，猫和"哲学"隔了整座城**。

于是"猫坐在垫子上"听得多了，再听到没听过的"狗坐在垫子上"，电脑一想：狗就在猫旁边那位，差不多——就敢接。**靠"意会"，不靠"死记"。**

**毛病二：只能记两三个词 → 从"传话游戏"到"随时翻旧账"。**

先替 N-gram 说句公道话：它不敢多记，不是懒，是账本太大。5 万个词，想记住"前两个词"的所有搭配，就要数 5万×5万×5万 那么多种组合，绝大多数一辈子空着；想记住前五个？硬盘直接撑爆。

后来有人想出 RNN：一边读，一边把前面内容压成一句"笔记"带着走。可这活像**传话游戏**——每传一人失真一点，传远了开头全忘。改进版 LSTM 给笔记加了"重点标记"，能多传几百米，还是不够。

真正的解法是**注意力机制**（2014）：不记笔记了，需要时直接**翻回原文**，该看哪句看哪句，隔多远都不累。2017 年的 Transformer 把这招用到极致：彻底不搞传话，全靠翻旧账，而且一帮人可以同时翻——训练速度暴增，模型越堆越大。

**最后一步纯属意外：喂多了，开窍了。**

同样的架构，数据和参数扩大一千倍，模型突然会没人教过的本事——看两个例子就学会答题，听得懂人话了。这叫"涌现"。2022 年 ChatGPT 再请"人类老师"打分调教，它就从续写机器变成了聊天助手。

它干的还是"猜下一个词"的老本行，只是不再翻次数表，而是靠意会。所以 N-gram 被后来者收编了：**Transformer 本质上就是一张无限厚、会自己更新、还带理解力的"次数表"。**



### 到底什么是神经网络

**它是对人类大脑神经元运作方式的一种”拙劣“但极其有效的数学模仿。**

#### 一、"神经元"这名字挺唬人，其实它干的活蠢得要命

人脑里有近千亿个神经元，互相用突触连着。信号过来了，觉得重要就加强，不重要就压下去。

计算机借了这么个名字。但你真去看单个神经元在干嘛，会失望的——它就干三件事：

- 把进来的信号按重要程度加在一起，重要的乘个大数，不重要的乘个小数

- 加完看一眼，够没够一个门槛

- 够了就往下传，不够就闭嘴

没了。就这点活儿。

真正厉害的不是某一个神经元，是几千亿个这么蠢的小东西，一层一层摞起来，摞几百层。

#### 二、那些"重要程度"，就是旋钮

每个重要程度是个数字，行话叫权重，你就理解成旋钮。

别把它想成什么"一个巨大的数学公式"，这说法容易让人以为有人把它写出来了。更准的画面是：一张网，网里几千亿根管道，每根的粗细都能调。

实际情况是：网长什么样，是人搭的；但里面那几千亿个数值，是机器自己试出来的，谁也看不懂，连写它的人也看不懂。

有多大？GPT-3 一个模型，1750 亿个旋钮。

刚造出来的时候，这些旋钮全是瞎拧的，所以它答出来的东西一塌糊涂。

#### 三、那它是怎么学会的

很简单，就是刷题：

- 给它看一张标了"猫"的照片，它猜：猫 12%、狗 60%、车 28%

- 拿标准答案一对，算出来它这回错得有多离谱

- 然后是最妙的一步：数学上能算出来，这次的错误里每个旋钮各背了多少锅，于是所有旋钮按背锅的比例，往反方向拧一丁点（这步叫反向传播）

- 换张照片，再来

几百万次、几十亿次，就这么磨下去。

全程没人告诉它"尖耳朵加胡须就是猫"。这套标准是它自己从例子里一点点凑出来的。

再说一遍：不是有人坐在那儿拧旋钮，是它自己刷题，错了自己改，这就叫训练。

#### 四、它不是背答案，是找手感

第一千零一只它从没见过的猫，它也认得。它记住的是"猫长什么样"，不是某张具体的照片。

当然也有翻车的时候：练习题要是太少、太偏，它就退化成死记硬背了（这叫过拟合），换张卷子就废。

#### 五、它为什么会一本正经地胡说八道

很多人以为是"它没把握也得硬选一个"。这只是一部分。

更关键的是：它从被造出来的第一天起，任务就是"猜下一个最可能出现的字"，不是"说真话"。

它脑子里没存一份事实清单，只有"哪个词接在这儿最顺"。所以它能用最真诚的语气，跟你讲最离谱的事。



### 多层架构

输入层 / 隐藏层 / 输出层，到底是什么

#### 一句话先说清楚

**输入层是你的嘴，输出层是它的嘴，中间那一堆隐藏层，是它的脑子。**&#8203;

你只能控制喂什么进去、看它吐什么出来；中间在想什么，你管不着，也看不懂。

#### 一、整体长什么样

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│   输入层      │      │   隐藏层      │      │   输出层      │
│              │      │              │      │              │
│   ●    ●     │      │   ●    ●     │      │   ●    ●     │
│              │ ───▶ │              │ ───▶ │              │
│   ●    ●     │      │   ●    ●     │      │              │
│              │      │              │      │              │
│   ●    ●     │      │   ●    ●     │      │              │
└──────────────┘      └──────────────┘      └──────────────┘
   你喂进去的           它自己捣鼓的           它吐出来的
```

每个 ● 是一个神经元。真实网络里，隐藏层不是一个方框，是几十上百个方框一个接一个串起来——那才叫"深度"。

#### 二、三层各自干什么

|            | 干什么               | 谁决定的   | 你能不能看懂           |
| ---------- | -------------------- | ---------- | ---------------------- |
| **输入层** | 把你的东西翻译成数字 | 你决定     | 能，就是原始数据       |
| **隐藏层** | 一层层往上做抽象     | 训练决定   | 不能，一堆没意义的数字 |
| **输出层** | 把最后的结果变成答案 | 你决定格式 | 能，就是答案           |

补充三点：

- **输入层其实不算"计算"。**&#8203; 它只是个入口，把一张照片拆成一堆数字，或者把一句话拆成一串词编号。
- **隐藏层才是干活的主力。**&#8203; 我们说"GPT-3 有 96 层"，数的就是它。
- **输出层是最后一层计算 + 一个转换。**&#8203; 先算出几个分数（猫 4.2、狗 0.1），再过一个叫 softmax 的转换，变成加起来等于 100% 的概率（猫 92%、狗 8%）。

#### 三、放大看：一层里面在算什么

```
        旋钮(权重)              求和              过门槛

  x₁ ──[× 0.8]──┐
                │
  x₂ ──[× 0.1]──┼────▶  ( 全加起来 )  ────▶  ( 够不够？ ) ──▶ 往下传一个数
                │
  x₃ ──[× 0.5]──┘

  0.8×x₁ + 0.1×x₂ + 0.5×x₃  =  一个数
                                   超过门槛 → 这个数往下传
                                   没超过   → 传 0（也就是闭嘴）
```

就这点活儿。那些 ×0.8、×0.1、×0.5 就是旋钮，也就是"权重"。训练调的就是它们。

#### 四、走一遍真实数字

```
输入层：[200, 30, 100]
           │
           ▼
隐藏层第 1 个神经元：0.8×200 + 0.1×30 + 0.5×100 = 213   → 超过门槛 → 输出 213
隐藏层第 2 个神经元：0.2×200 + 0.9×30 + 0.1×100 = 77    → 没超过   → 输出 0
隐藏层第 3 个神经元：0.6×200 + 0.4×30 + 0.7×100 = 202   → 超过门槛 → 输出 202
隐藏层第 4 个神经元：0.1×200 + 0.2×30 + 0.3×100 = 56    → 没超过   → 输出 0
           │
           ▼
输出层：把 [213, 0, 202, 0] 再加权求和一次
           │
           ▼
        猫 92%  ·  狗 8%
```

真实网络里，输入不是 3 个数字而是几万几十万个，隐藏层不是 4 个而是几千上万个，而且中间要穿过几十上百层。但每一层干的事，跟上面一模一样。

#### 五、三个最常见的追问

**1. 隐藏层为什么叫"隐藏"？**

因为它的数值对外是不可见的，也是不可解释的。输入是什么（一张照片）、输出是什么（猫还是狗），都是人规定好的。但中间那一层算出来的 213、0、202、0，没人规定它们必须代表什么，也真的没人知道它们代表什么。对外部来说，这一层是藏起来的——所以叫隐藏层。

**2. 输入层算不算"一层"？**

不算。业界说"这个网络有多少层"，数的是隐藏层（有时加上输出层），输入层不计数。所以"96 层"= 96 个隐藏块，不是 98 层。

**3. 不要隐藏层行不行？**

行，但那就废了。没有隐藏层的网络只能学"直线"的规律——比如在图上画一条直线把猫和狗分开。现实里的分界线都是弯的、绕的，直线切不开。每多一层隐藏层，就多一次"把上一层的输出重新组合"的机会，能画的边界就更弯、更复杂。这就是"深度"的全部意义。

#### 收个尾

| 名称   | 一句话                       |
| ------ | ---------------------------- |
| 输入层 | 把你的问题翻译成数字         |
| 隐藏层 | 一层层往上做抽象，主力全在这 |
| 输出层 | 把最后的结果翻成人能懂的答案 |

整个网络 = 入口 + 一堆重复的抽象工序 + 出口。中间那堆工序长得一模一样，只是旋钮数值不同。

#### 举个例子

上周你在地铁口，隔着二十米、逆光、人挤人，你一眼认出了老同学张三，脱口喊出他名字。这整个过程，就是一次神经网络的完整运行。

输入层，就是你的视网膜。那一刻它收到的只有一堆光点：亮的、暗的、颜色深浅。就这些，里面没有"张三"这三个字。

隐藏层，是接下来几毫秒里发生的事。你的脑子把光点拼成边缘，把边缘拼成轮廓，把轮廓拼成"这个身高、这个肩宽、走路一颠一颠的姿势"，再往上拼成"这张脸的眉眼间距"。

关键在于——这一整段，你自己完全说不出来。你现在试试描述一下，你是怎么从一堆光点认出张三的？你说不出来。你只知道答案，不知道过程。

这就叫"隐藏"。不是被人藏起来了，是连使用者自己都讲不清。神经网络的隐藏层一模一样：你喂进去一张图，它吐出来一个答案，中间那几百层的数字代表什么，谁也解释不了。

输出层，就是你开口喊"张三"那一下。到这一层，答案必须变成人能懂的形式。

再往下就有意思了：

他换个角度、理个发、胖了五斤，你还认得。因为你记的不是某一张照片，是"特征组合"。这就是泛化。

但如果他那天穿了件特别扎眼的红外套，你事后说"哦我是靠那件红外套认出他的"——那就完了，明天他换件黑的你就不认得了。这就是过拟合：记住了无关紧要的细节，没记住真正的规律。

最后，光线再暗一点，你八成还是会对着一个陌生人喊一声"张三"。不是你眼瞎，是你这套系统里压根没有"我不知道"这个按钮，它必须给个答案。AI 一本正经地胡说八道，就是这个毛病。

所以：输入层是你眼睛里的光点，输出层是你嘴里喊出的名字，中间那一段你说不清、道不明、但确实在起作用的东西——就是隐藏层。

### 反向传播

先看一个问题，比如面试录用了 10 个人，结果三个约之后老板拿着绩效在拍桌子：招的这 10 个人，只有 1 个干活的，剩下 9 个都在摸鱼！公司亏了几百万。**这几百万亏损在 AI 里叫”亏损函数（Loos Function）-- 预测结果与真是结果之间的差距。**

那么怎么修正这个错误？不能只骂人，必须“倒查责任”。

1. 老板骂总监：你怎么招的人？你的判断标准（权重）要改。
2. 总监骂经理：是你推荐那个莫欲望的，你的用人标准得改改。
3. 经理骂 HR：是你把那个简历初筛进来的，以后别光看学历，要看项目经验。

原理： 深度学习的灵魂 -- 反向传播。通过错误的结果去反向寻找，到底哪个参数影响整个结果的作用最大，然后不断去调整优化它。

- 正向传播是“数据从下网上汇报”
- 反向传播是“误差从上往下分摊”
- 每一次被骂（计算梯度），每个人调整一点点自己的权重。

**反向传播就是一次"错题复盘"——先看看错在哪，再倒着往前追，算出每个旋钮该为这次错误背多少锅，然后按锅的大小去拧它。**

数据标注是不是反向传播？

完全不是一回事，它俩一个在训练**之前**，一个在训练**之中**；一个是人干的，一个是机器干的。一个是告诉你正确答案是什么，一个是倒着复盘自身的错误。

**标注是"标准答案从哪来"，反向传播是"拿到答案之后怎么改"。**

### 过拟合

过拟合(Overfitting)就是**死记硬背**——练习题上几乎满分，换个数字就不会了。

驾校倒库，教练教你："看到左边第三根杆，方向盘打死。" 你在驾校练了二十遍，次次一把进。你以为你会倒车了。

结果考试换了考场，杆子位置变了，你压线，挂了。

你学到的是什么？不是"车感"——不是车身跟边线什么关系、方向盘一打车尾往哪摆。你记住的是"第三根杆"。那是那个考场碰巧才有的东西（噪声）。

**记住了巧合，没记住规律。** 这就是过拟合。



怎么解决？

1. **多给题、给杂题。** 各个考场都去练，它就没法靠背点位混过去了。
2. **早点停。** 练到差不多就收手，再练下去它就开始背答案了。
3. **给它立个规矩：旋钮不许拧得太极端。** 因为某个旋钮一旦拧得特别大，多半是在死磕某个具体例子的细节。逼它拧得温和些，它就只能用更通用的方式解题。这叫正则化。
4. **训练时随机让一部分神经元闭嘴（丢弃法 Dropout）。** 这招最有意思——就像球队训练时随机抽掉几个主力不让上场，逼着替补也必须学会配合。谁都不能偷懒，全队都得真会。这叫 dropout，是深度学习里最管用的防死记硬背手段之一。

过拟合的反义词不是"聪明"，是"泛化"。衡量一个模型好不好，从来不看它在练习题上考几分，只看它在新题上还行不行。反过来，如果练习题它都做不对，那叫欠拟合——练得不够，或者模型太笨。

### 学习率

学习率（Learning Rate）就是**每一步迈多大**。如果步子迈太大，错误不降反升，整个训练直接崩了。迈的太小随便一个小土坑就能把你困住，你还以为到底了。

**正合适的做法是：先大步走，再小碎步。**

- 刚开始不懂的时候，步子大一点，快速试错
- 快要找到规律的时候，步子小一点，精细微调

### 梯度下降

梯度下降就是**蒙着眼，一步一步摸索着往山下走**。

- **梯度**，就是"你脚下这一点的坡度"——往哪边倾斜、倾斜得多厉害。放到神经网络里，它是一张清单，写着几千亿个旋钮各自的情况：这个拧大一点错误会涨 0.6，那个拧大一点错误会降 0.2。

- **下降**，就是顺着坡往下走。我们的目标是把错误压到最低，所以永远朝"错误变小"的方向挪。

合起来，梯度干的事就是重复两件事：**探一下坡度，往下挪一步。再探，再挪。** 几百万次之后，你就到某个山谷的底部了。

为什么非要这么笨地一步步挪，不能直接算出最低点在哪？因为几千亿个旋钮搅在一起，那个方程根本解不出来。看不见全山，只能在脚下探。



**反向传播** = 测坡度的那套方法，往回走一遍，几千亿个旋钮的坡度一次性全测出来
**梯度** = 测出来的结果，那张"谁该拧多少"的清单
**梯度下降** = 拿着清单真的去挪的那套策略
**学习率** = 每一步挪多大

所以是：反向传播算出梯度 → 梯度下降按梯度去拧 → 学习率决定拧的幅度。一环扣一环，但不是一回事。

### 调参

神经网络里有**两批旋钮**，别混了。

- **参数（权重）**：几千亿个，训练时反向传播自动拧。机器干，人不碰。
- **超参数**：开工前人设的，决定"网络长啥样"和"怎么练"。机器不碰，全靠工程确定。

**"调参"调的就是后者。** 不是去拧那几千亿个旋钮（那是刷题中干的），而是开工前把"训练该怎么进行"那批开关一个个确定。



常见的超参数：

| 超参数           | 决定啥             | 举个栗子                       |
| :--------------- | :----------------- | :----------------------------- |
| 学习率           | 每步迈多大         | 太大发散、太小慢死             |
| 网络深度         | 摞几层             | 越深越抽象，但难训练           |
| 网络宽度         | 每层多宽           | 一层能同时装多少特征           |
| 批量大小 batch   | 一次抓几张图估坡度 | 32 张估个大概就迈一步          |
| 训练轮数 epoch   | 把题刷几遍         | 太多→背答案（过拟合）          |
| 正则化 / dropout | 防死记硬背的力度   | 旋钮别拧太狠、随机让神经元闭嘴 |
| 优化器           | 用哪套走法         | Adam 是最出名的那个            |

反向传播 + 梯度下降 = 自动拧"参数"；调参 = 人给这套自动拧的机器**定规矩**。



## LLM 模型训练的核心流程

神经网络训练的核心循环，本质上就是一套“做题—对答案—纠错”的流程：

**1. 准备数据**
从训练集中取出一小批样本（batch），每个样本都带有真实标签——比如 256 张图片，各自标注了“猫”或“狗”。

**2. 前向传播**
数据逐层流过网络——加权求和、非线性激活，一路传递到输出层，得到预测结果：这张图有 73% 的概率是猫。

**3. 计算损失**
用损失函数（交叉熵、均方误差等）量化预测与真实标签的差距。这一个数字，就是模型的“错误程度”。

**4. 反向传播**
以损失为起点，用链式法则逐层回溯，算出每个参数对这次错误的“贡献量”——即梯度。

**5. 梯度下降**
沿梯度反方向、以设定的学习率微调每个参数，让下一次预测的错误比这次小一点——如同下山时，每一步都朝最陡的下坡方向迈。



这个循环会重复数十亿次，直到模型足够聪明，预测与真实标签的差距小到可以接受。此时损失曲线趋于平缓，一组最初纯属随机的权重，逐渐收敛为能捕捉数据规律的参数。

所谓“学习”，不过是**用数学方法，把错误一点一点磨掉**。

## LLM 参数越多越聪明吗

### **参数是什么？**

就是模型里那些可以被训练调整的数字（权重）。训练循环每跑一轮，被微调的就是它们。7B 模型 = 70 亿个这样的数字。

**参数多的好处**

| 方面             | 说明                                                         |
| :--------------- | :----------------------------------------------------------- |
| 记得多           | 参数像存储格子，更多参数能装下更多知识和语言规律             |
| 学得细           | 能捕捉细微差别：反讽、双关、代码里的深层逻辑                 |
| 能力会“突然出现” | 规模到某个临界点，模型表现出训练目标里没直接教过的能力（如多步推理），这叫**涌现能力** |
| 更抗糊涂         | 复杂指令、长上下文里更不容易迷失                             |

**参数多的代价**

| 方面     | 说明                                                         |
| :------- | :----------------------------------------------------------- |
| 跑得慢   | 推理要做的计算量随参数量增长，响应变慢                       |
| 吃显存   | 7B 模型 fp16 约需 14GB 显存，70B 约 140GB——消费级显卡直接劝退 |
| 训练贵   | 训练成本随规模指数级上升，只有大厂玩得起                     |
| 边际递减 | 参数翻 10 倍，效果并不会好 10 倍，提升越来越“不划算”         |

**关键规律：参数不是唯一变量**

同样的参数量，喂更多、更好的数据，效果能大幅提升。所以现在趋势是：

- **不盲目堆参数**——在参数量、数据量、算力三者间找最优配比
- **MoE（混合专家）**——总参数很大，但每次推理只激活一小部分，兼顾容量与速度
- **小模型 + 好数据 + 针对性训练**——在具体任务上可以打赢大它很多倍的通用模型

参数量决定模型“聪明上限”，但能不能达到上限，还看数据质量、训练方法和推理成本 —— 大不一定强，小不一定弱。

## LLM 是如何回答床前明月光的下一句

**阶段一：训练时，把答案“焊”进参数里**

用的就是之前聊的那个循环（前向传播 → 算损失 → 反向传播 → 梯度下降）：

- 训练数据里，“床前明月光\n疑是地上霜”这个组合出现了无数次
- 模型一开始是乱猜的，给它“床前明月光”，它可能输出任何字
- 损失函数告诉它：错了，标准答案是“疑”
- 梯度下降微调几十亿参数中的一个很小角落：让出现“疑”的概率 +0.001%

这个循环跑了数十亿次之后：

> 输入“床前明月光” → 输出概率里，“疑”排第一，“是”“月”等排在后面

**阶段二：回答时，按概率逐字往外蹦**

1. 把你的问题切成一串 token（字/词的碎片）
2. 前向传播：结合上下文，算出词表里每个字的概率
3. **“疑”字概率最高，被选为第一个字**
4. 把“床前明月光，疑”拼回输入，重算一次——“是”胜出
5. 如此循环，“地”“上”“霜”依次蹦出来，凑成“疑是地上霜”

## 蒸馏模型

### 一、核心思想：师父带徒弟

大模型（教师模型）什么都好，就是太贵太慢——参数量大，跑一次推理烧半张显卡。

蒸馏的想法是：**让大模型当老师，把它身上最值钱的东西——处理问题的“思路和手感”——教给一个小模型**。小模型出师后，个头小很多，但干活质量接近师父。

它不是抄完的，是教出来的：

- **笨办法（直接拿数据训练小模型）**：相当于给学生看标准答案。每道题只有一个正确答案，对错分明。
- **蒸馏**：师父把每道题的完整解题过程演示一遍，包括**当时是怎么犹豫的**。

### 二、关键机密：软标签（Soft Labels）

这是蒸馏最核心的一点。

普通训练给学生的答案是这样的：

> 识别动物图片：猫 ✓，狗 ✗，汽车 ✗

这叫**硬标签**——非黑即白。

师父演示时给的是这样的：

> 识别动物图片：猫 73%，狗 24%，狐狸 2%，汽车 0.1%

这叫**软标签**。注意那 24% 的“狗”——这就是**师父的思考痕迹**，也叫“暗知识”（dark knowledge）：

- 学生从硬标签只能学到：猫不是狗
- 学生从软标签能学到：**猫和狗有几分相似，但更像猫**——这个相似度信息本身就是知识

一只小模型能学到多少这种细腻判断，直接决定它出师后的水平。

为了让软标签更“软”（分布更平滑，次高概率别被压得太低），训练时还会加一个**温度参数**——把概率分布整体“抹匀”一点，让师父的犹豫更充分地暴露出来，学生才学得全。

### 三、蒸馏的完整流程

```plaintext
1. 先养一个教师模型（大模型，效果已验证）
        ↓
2. 让教师在大量数据上跑一遍，记录它输出的概率分布（软标签）
        ↓  这一步只推理、不训练，教师参数冻结
3. 用这些软标签训练学生模型（小模型）
        ↓  通常：软标签损失 + 真实硬标签损失一起用
4. 出师：学生模型比正常从零训练的小模型强得多
```

一个具体例子：DeepSeek-R1 发布后，官方用它的输出作为训练数据，蒸出了一系列 **R1-Distill** 模型——基于 Qwen、Llama 等 1.5B 到 70B 的小模型，在数学推理等任务上远超同量级自己训练的模型

**模型蒸馏是“让大模型当老师，用它的完整思考过程教出一个小而强的学生”的压缩技术；蒸馏模型就是这个技术蒸出来的成品。**

## 量化

模型本身就是一堆数字（权重）。默认训练出来的每个数都是 **fp16**（16 位浮点，约 6 位有效数字）——相当于每次测量都精确到微米。

问题是：**大多数权重根本用不上这个精度**。就像测房间长度，卷尺精确到毫米够用了，没必要上激光干涉仪。

量化的做法：把权重从 fp16 压成 **int8**（8 位整数）、甚至 **int4**（4 位整数），每个数的表达空间骤降，但挑选的位数刚好够用。

压缩前后的损耗直观可见——以 70 亿参数（7B）模型为例：

| 精度         | 权重占用 | 能塞进哪         |
| :----------- | :------- | :--------------- |
| fp16（原版） | ≈ 14 GB  | 单张 24G 显卡    |
| int8         | ≈ 7 GB   | 甜点显卡         |
| int4         | ≈ 3.5 GB | 一块游戏本、手机 |

**量化不改模型结构、不重新训练，只是把权重的数字精度降低，让模型“缩水”到能塞进消费级硬件——是当前让大模型在本地跑起来最主流的手段。**

## Transformer

### 演进史

在 TransFormer 出来之前，实际上技术发展的路线是：N-gram → Embedding → RNN → LSTM

1. **N-gram：统计语言模型，词频概率**
   - 核心思路：通过统计前面几个词出现后，下一个词出现的条件概率。
   - **局限性**：N-gram 只会死板地做统计，**无法理解词语之间的语义关系**（例如它不知道“猫”和“狗”都是动物）。

2. **Word Embedding：词嵌入向量，高维语义映射**
   - **核心思路**：词向量把每个词变成一组高维浮点数（如 `[0.9, 0.3, 1.1, -0.89, …]`），把词语的**含义**映射进这组数字里——语义相近的词，在向量空间里的位置也更接近。有了词向量，再把它交给前馈神经网络（FNN），让网络学习更复杂的语言规律、预测下一个词。（最早把词向量接进神经网络做预测的是 Bengio 2003 的 NNLM。）
   - **FNN 的瓶颈**：早期将词向量送入前馈神经网络（FNN）来预测下一个词。但 FNN **一次只能接收固定数量的文本**，且无法很好地捕捉时序和位置信息，因此引入了循环结构。

3. **RNN：循环神经网络，时序记忆**
   - **核心思路**：引入了“隐藏状态（Hidden State）”RNN 增加了一份不断向后传递的「隐藏状态」，相当于给模型加了**记忆**，让前面的信息可以一直往后流动。
   - **局限性：**RNN 的长期记忆能力不行：距离一长，前面的重要信息在传递中逐渐衰减、丢失（梯度消失）。

4. **LSTM：长短期记忆，门控机制**

   - **核心思路**：引入了“细胞状态（Cell State）”这条长期记忆通道，并设计了**遗忘门、输入门、输出门**，让模型自主学习什么该记住、什么该忘掉。

   - **核心痛点：**尽管改善了长期记忆，但 LSTM 依然存在两个致命问题：

     1. **串行计算效率极低**：必须严格按照 Token 顺序一个一个计算，前一个没算完，后一个就无法开始，**无法进行大规模并行训练**。
     2. **长距离依赖瓶颈**：两个相距很远的 Token 如果要交换信息，必须穿过中间所有的 Token 一步步传递，信息在漫长的串行路径中仍会模糊。

     

**Transformer** 正是针对 LSTM 的这两大痛点应运而生。它放弃了循环结构，改用**自注意力机制（Self-Attention）**，让文本中任意两个词之间都能“一步直达”建立联系，并实现了完美的**全文本并行计算**。



Transformer 是 Google 2017 年提出的深度学习架构，也是 GPT、Claude 等大模型的基石。

**它解决的问题： 让机器理解一句话中词与词之间的关系。**

老方案（RNN）的两个致命缺陷：

- 必须逐词顺序处理，无法并行，训练慢
- 长序列中信息会衰减遗忘，难以捕捉长距离依赖

Transformer 的做法： 完全抛弃循环结构，只用注意力机制（Attention）一眼看全句，直接计算任意两个词之间的关联。

带来的三大优势：

1. 高度并行化，训练速度大幅提升
2. 长距离建模能力更强，再远的词也能建立联系
3. 可扩展性好，为千亿参数大模型铺平道路
一句话： 从“逐字读”变成“整体看”，用注意力取代循环，又快又准。

### Transformer 核心原理

#### 自注意力机制（Self-Attention）

这是 Transformer 的灵魂。机制其实很生活化。

**场景**：「小明把苹果给了小红，因为她饿了。」

**原理**：RNN 只能一个词一个词传话，而 Transformer 里的每一个词，都会和句子里的其他所有词进行**「两两打分」**（计算相关性权重）。「她」和「小红」相关性最高，最终「她」的语义向量里就会融入大量「小红」的信息。

为了在数学上实现这个「打分」，Transformer 让每个词通过三组不同的权重矩阵（`W_Q`、`W_K`、`W_V`）进行线性变换，分身出三种角色：

| 角色       | 类比              | 作用                          |
| ---------- | ----------------- | ----------------------------- |
| Query（Q） | 我在找什么        | 发出的检索请求                |
| Key（K）   | 我是谁 / 我的标签 | 亮出的特征，供别人的 Q 来匹配 |
| Value（V） | 我携带的实际语义  | 匹配成功后，实际贡献出的内容  |

**流程**：`Q` 和每个 `K` 做点积得到关联分数 → 除以 `√d_k` 缩放、再过 `softmax` 归一化 → 按权重加权求和所有 `V`。

两个细节值得点名：

- **为什么要缩放？** 向量维度越高，点积值天然越大，直接 `softmax` 会让分布过于陡峭（高分独占、其余几乎归零，梯度消失）。除以 `√d_k` 是给分数「降温」。这也是这套机制叫**缩放点积注意力（Scaled Dot-Product Attention）**&#8203;的原因。
- **为什么要 `softmax`？** 把任意分数变成一组加起来等于 1 的权重，这样对 `V` 的加权求和才是一个稳定的「凸组合」——新词义是旧词义按比例混合出来的，而不是无界放大。

这就实现了：**每个词的最终含义，由它最相关的那些词共同决定**。词义不再是查字典查出来的，而是看上下文算出来的——「苹果」在「吃苹果」和「苹果发布会」里表示不同，靠的就是这个。

#### 多头注意力（Multi-Head Attention）

只有一套 `QKV` 肯定不够。一句话里词与词的关系不止一种，比如：

> 「我小时候养过一只虎皮鹦鹉。它有绿色的羽毛。」

「它」和「虎皮鹦鹉」之间是指代关系，「绿色」和「羽毛」之间是修饰关系，「我」和「养过」之间是动作关系，「养过」和「虎皮鹦鹉」之间又是一种搭配关系。

也就是说，一句话里可能同时存在语法关系、指代关系、语义关系等多种关系，只有一套 `QKV` 很难同时兼顾。那就多来几套：每组各自做一次注意力计算，各自专注一类关系。每一个头具体学到什么关系，是由训练决定的，事先并不指定。最后把各头的结果拼接起来，形成更丰富的表示。

这种从多个角度同时做注意力的方法，就是多头注意力。所谓一个「头」，可以理解为一组独立的 `QKV` 计算。一个角度看不明白，那就多个角度一起看。

#### 位置编码（Positional Encoding）

在矩阵计算里，「我打你」和「你打我」变成了完全一样的东西。注意力机制只计算词与词之间的相关性，它天然不感知顺序。所以需要在词向量上额外叠加一份专门表示位置的信息——这样模型收到的就不再只是「这个词是谁」，还知道「这个词在第几位」。这份信息就是位置编码。

原始 Transformer 用正弦、余弦函数生成位置编码，而且这组编码是固定的，不参与训练。现在的大语言模型普遍改用**旋转位置编码（RoPE，Rotary Position Embedding）**&#8203;。为什么改？因为 RoPE 通过数学上的旋转操作，让 `Q` 和 `K` 在做点积时只依赖两个词之间的相对距离——这是精确的数学性质。至于「距离越近的词通常越相关、分数越高」，则是模型在训练中学到的统计模式，而不是旋转本身的必然结果。

到这里，词向量告诉模型 Token 的语义，位置编码告诉模型 Token 的顺序。每个 Token 带着语义和位置信息，通过多头注意力和其他 Token 大规模交换信息。

#### 并行计算与因果掩码

**RNN 为什么慢？** 它每一步的隐藏状态都依赖上一步的输出，第 t 个词必须等第 t−1 个词算完才能开始——是一条串行的链条。GPU 上千上万个核心在旁边干瞪眼，明明能并行，却被这种「依赖链」锁死了。

**Transformer 怎么破？** 既然每个词都和所有词两两打分，那这些打分之间根本没有先后依赖。整句话的词向量打包成一个矩阵，一次性丢给 GPU，所有词对的关联分数在同一时刻并行算完。数学上就是一句话的事：`QKᵀ` 这一个矩阵乘法，直接吐出包含**所有 token 两两分数**的完整分数矩阵——没有串行，全是并行。

**问题：训练时整个句子一起喂，模型会不会偷看未来的词？** 会。如果任由「我打你」里的「你」去和后面的词打分，模型就等于提前知道答案，训练出来的不是「根据上文预测下一个词」，而是「看着全文填空」。

**因果掩码（Causal Mask）就是用来堵这个洞的。**&#8203; 可以把因果掩码想成一张访问权限表：对当前 Token 来说，它可以参考自己和前面的 Token，但不能参考未来位置的 Token。

#### 前馈神经网络（Feed-Forward Network，FFN）

到这里，Attention 已经让 Token 之间交换了信息。接下来有个自然的问题：**Token 拿到上下文信息后，还需要把这些信息加工一下吗？**

需要。这就是前馈神经网络（Feed-Forward Network，简称 **FFN**）的工作。想要弄清楚 FFN，先要理解三个问题：

1. FFN 拿到的到底是什么东西？
2. 它具体对这些东西做了什么加工？
3. 加工完之后，这些结果被拿去干什么了？为什么还要继续传给下一层？

在理解之前，先搞清一个事情：

假设我们让模型理解下面两句话：

> ① 我吃了一个苹果，这个苹果很甜。
> ② 苹果发布了一款新手机。

你会发现，虽然两句话里都有「苹果」，但含义不一样。第一句说的是水果，第二句说的是公司及其产品。Transformer 要处理的一个重要问题，就是让同一个 Token 的表示能够随着上下文发生变化。那么，具体是谁在做这件事？不是 FFN 单独完成的，而是整个 Transformer 中的多个模块一起完成的。

我们先把流程简化成这样：

    第一步：Token 进入模型
    「苹果」最初有一个向量表示
            ↓
    第二步：Attention
    从其他 Token 汇集上下文信息
            ↓
    第三步：FFN
    重新组合特征，让向量得到进一步加工

这里先记住一个关键区别：

- **Attention** 主要解决「我应该从其他 Token 获取什么信息」。
- **FFN** 主要解决「我拿到当前这些信息后，怎样进一步加工它们」。

注意，Attention 输出的不是一段中文解释，而是一个经过计算更新后的向量。FFN 也是如此，它不会直接输出「苹果是水果」这种结论，而是把向量加工后交给后面的网络继续使用。

**1. FFN 拿到的到底是什么东西？**

假设我们现在处理第二句话：「苹果发布了一款新手机。」为了方便理解，我们只盯着「苹果」这一个 Token。

前面的 Attention 已经让它接触到了「发布」「新手机」等上下文信息。所以，这时候「苹果」的向量，已经不再只是最初的词语表示，而是一个融合了当前上下文信息的表示。

你可以暂时把它想成一份刚开完会的工作记录：

- 记录里有原本就知道的内容。
- 记录里增加了周围同事提供的信息。
- 这些信息已经混在一份新的记录里，但还需要进一步整理。

这份「工作记录」，就是 FFN 接下来要处理的输入。

这里有个容易忽略的细节：向量不是一份能直接读懂的中文文档。它是一组数字，语义信息分散地体现在许多数字及其相互关系中。我们说它包含了「公司」「产品」等信息，是为了方便理解，不是说向量里一定有几个明确标注的字段。

**2. FFN 到底怎么加工？我们拆成三个动作**

经典的 FFN 可以理解为：先把特征展开，再经过非线性处理，最后重新组合。

**第一步：把原来的特征展开**

假设模型内部给每个 Token 分配了一个很长的向量，里面有几千个数字。FFN 的第一步，是用一层全连接网络，把这个向量映射到一个更宽的隐藏空间。

例如，原来的表示有 512 个维度，经过扩展后，中间表示可以有 2048 个维度。这是原始 Transformer 中的一个典型配置，实际模型的维度会有所不同。

这一步并不是把原有数字简单复制几遍，而是通过一组训练得到的权重，计算出大量新的特征组合。

**这到底是什么意思？** 想象你正在分析一条商品信息。原始资料中包含名称、价格、品牌、用途等许多线索。你不只关心每一条单独的线索，还想从它们的组合中提取更多信息。例如：

- 名称和用途放在一起，可能反映商品类别。
- 品牌和产品信息放在一起，可能反映产品归属。
- 产品信息和发布相关的上下文放在一起，可能有助于识别某种事件。

FFN 的第一层可以做类似的事情：**它根据输入向量里的多个特征，计算出许多不同的组合响应。**&#8203;

    第一层：生成更多中间特征
    输入向量（当前 Token 已经包含的上下文信息）
            ↓
    中间特征 A（某种特征组合）   中间特征 B（另一种特征组合）
    中间特征 C（又一种特征组合）  ……（更多隐藏特征）

因此，第一步的重点不是「存储了多少个数字」，而是：**通过可训练的权重，把原来的表示变换到一个更宽的空间，给后续计算提供更多特征组合的可能性。**&#8203;

**第二步：通过激活函数，改变这些特征的响应方式**

刚才第一层生成了一大批中间特征。但如果网络从头到尾只做线性变换，那么即使连续堆叠很多线性层，整体仍然可以合并成一次线性变换，表达能力会受到很大限制。

因此，FFN 要加入一个关键步骤：激活函数。过非线性激活（ReLU/GELU）：像筛子，把不相关的维度压下去、相关的留下。相当于「针对当前这个已被上下文充实的 token，判断哪些特征值得强调」。

**第三步：把中间特征重新组合，生成新的向量**

现在，我们已经得到了经过激活函数处理的一批中间特征。下一步，FFN 会通过第二层全连接网络，再次把这些特征组合起来，映射回模型需要的维度，例如原来的 512 个维度。因为 Transformer 中的各个子模块需要按照约定的隐藏维度衔接。

- 第一层，产生大量不同的中间特征。
- 第二步，对这些特征做非线性处理。
- 第三层（即第二层全连接），把它们重新组合成一个新的表示。

**最终得到的并不是一句答案，而是一个经过加工的新向量。**&#8203;

**3. 加工之后，到底拿去干什么了？**

FFN 并不是一个独立的任务终点。它加工出的向量，是后续 Transformer 计算继续使用的输入。

把神经网络想成一条加工流水线。数据进来以后，会经过一站又一站的处理；每一站做一类计算，把结果交给下一站。这类处理步骤常被叫作「层」（Layer）。一般一个完整的 Transformer Block 被称为一层：

- **Attention（注意力）**&#8203;：让不同 Token 彼此交换有用的信息。
- **FFN（前馈神经网络）**&#8203;：对每个 Token 已经拿到的信息再加工。
- **Residual Connection（残差连接）**&#8203;：给输入留一条直接通路，并把输入与子模块的结果相加。
- **Normalization（归一化）**&#8203;：调整隐藏向量的数值分布，例如使用 LayerNorm 或 RMSNorm。

可以把一个 Block 想成流水线中的一个完整工段：先交流信息，再各自加工，同时安排好信息传递和数值处理。为什么会有这么多层？简单来讲：**大模型需要通过「层层递进」的步骤，去瓦解人类语言极度复杂的抽象结构**。

所以加工之后可以分成两个部分去看：

1. 如果后面还有层，网络会把 FFN 输出的新向量与对应的输入通过残差连接结合起来，再归一化，然后传递给下一层。
2. 如果 FFN 是最后一层，那么 FFN 输出经过该架构要求的残差、归一化等操作后，会成为最后隐藏表示的一部分。接下来，模型会使用输出端的线性映射等结构，把这些隐藏表示转换成词表中各个 Token 的预测分数。然后，根据这些分数形成概率分布，再按照生成策略选择或采样下一个 Token。

例如，模型读完「我吃了一个苹果，这个苹果很……」，它可能对「甜」「大」「贵」等候选 Token 给出不同的预测分数。需要注意，这些预测分数不是 FFN 直接输出的，它们是在整个 Transformer 的多层计算完成之后，由输出端的结构生成的。

**FFN 加工向量 → 输出进入后续 Block → 多层计算不断更新表示 → 最后由输出端预测下一个 Token。**&#8203;

#### 残差连接（Residual Connection）

**先想象一个问题**

假设 Transformer 收到一个词，转换成了两个数字：`[2, 3]`。接下来，它要把这两个数字交给 FFN（前馈网络）加工。FFN 加工之后，得到：`[0.5, -1]`。

问题来了：原来的信息 `[2, 3]` 怎么办？如果只用 FFN 的结果，原来的数字就被替换掉了。

残差连接就是：把原来的信息加回来。

    原始输入 X：[2, 3]
            ↓ 一份送去加工
    FFN 加工结果 F(X)：[0.5, -1]
            + 加上原始输入 X
            ↓
    残差连接后的结果：[2.5, 2]
    即 [2, 3] + [0.5, -1]

你看，最后的结果不是单纯的 `[0.5, -1]`，而是把原来的 `[2, 3]` 加回来，得到 `[2.5, 2]`。这就是残差连接的核心：**加工可以改变信息，但不必完全丢掉原来的输入。**&#8203;

**为什么要这样设计？**

你可以把 FFN 想象成一个帮你修改文章的人：

- 原始文章：保留原文。
- FFN：提出修改和补充。
- 残差连接：把原文与修改产生的变化结合起来，而不是直接把原文全部丢掉。

**这样做有两个重要好处：**

1. **保留原始信息。**&#8203; 网络加工特征时，不必每次都从头重新表达原来的内容。
2. **让模型更容易训练。**&#8203; 原始输入可以沿着这条连接直接传递，有助于梯度传播，让深层网络更容易学习。

**解决了两个问题：**

1. **缓解网络退化**：让新增的层更容易学会「没必要就别乱改」。

   假设一个网络原本有 20 层，效果不错。你增加到 50 层，结果训练效果反而变差了，这就是网络退化。残差连接让每一层都可以学习：如果需要改变输入，就学习怎么改变；如果不需要改变输入，就可以学习接近于不改变它。因此，新增的层不必非得学出复杂的变换，深层网络更容易训练。

2. **缓解梯度消失**：让训练信号更容易传回前面的层。

   神经网络训练时，需要从最后往前传递梯度，指导前面的参数如何调整。网络很深时，梯度可能越传越小，前面的层就不容易学到东西。残差连接提供了一条更直接的梯度传播路径，因此可以缓解梯度消失，让深层网络更容易训练。

#### LayerNorm（归一化）：为什么需要归一化

假设 Transformer 正在处理一个词，它用 4 个数字表示这个词的特征。

处理前：`[2, 3, 4, 5]`

经过某一层网络加工后，数字变成了：`[200, 300, 400, 500]`

网络每一层都在加工特征，数值的大小和分布可能不断变化。这会让后续的计算和训练变得不那么稳定，模型可能更难找到合适的参数。

归一化就像给这些数字做一次整理，让它们处于更合适的数值尺度，变成更容易处理的数值：

    一组输入特征：[200, 300, 400, 500]
            ↓
        归一化（根据这组数字的统计特征，重新调整数值）
            ↓
    更容易处理的数值（数值尺度得到整理，帮助训练保持稳定）

**这里有个关键点：归一化不是把所有数字都变成一样，也不是简单地把数字变小，而是按照特定规则调整它们，同时尽量保留有用的特征差异。**&#8203;

**为什么神经网络中特征数值的尺度变化会让训练不稳定？**

假设神经网络正在学习判断一个人是否高，模型接收到两个特征：

- 身高：170 厘米
- 年龄：20 岁

模型要根据这两个数字，学习如何判断一个人是否高。身高是 170，年龄是 20。身高的数字比年龄大很多，但不代表身高就一定比年龄重要。数字大小和特征的重要性，并不是一回事。

假设模型正在调整自己的参数，试着找出哪些特征应该发挥多大作用。由于不同特征的数值尺度不同，参数调整时可能会出现不平衡：

- 某些方向上的参数调整，可能对结果产生很大的影响。
- 另一些方向上的参数调整，影响可能小得多。

训练时，不同方向的参数对结果的影响可能差别很大，优化过程就会更难控制。

#### Transformer Block：怎么工作

先讲一种常见的结构：Pre-Norm Transformer，也就是先归一化，再进行 Attention 或 FFN。现代很多 Transformer 都采用类似结构。

    输入 X
    每个词已经变成一组数字（特征向量）
            ↓
    ① LayerNorm / RMSNorm（归一化）：整理特征的数值尺度
            ↓
    ② Attention：让每个词结合其他相关词的信息
            ↓
    ③ 残差连接：加回原始 X
            ↓
    ④ LayerNorm / RMSNorm（归一化）
            ↓
    ⑤ FFN：进一步加工每个词自己的特征
            ↓
    ⑥ 残差连接：加回 Attention 阶段的输入
            ↓
    输出 Y：交给下一层 Transformer Block

### 编码器（Encoder）和解码器（Decoder）

先用一句话理解

- 编码器 Encoder： 负责理解输入，把输入加工成包含上下文信息的表示。
- 解码器 Decoder： 负责根据已有信息，逐步生成输出。



```text
输入英文:I love apples.
        ↓
Encoder 编码器
通过多层 Transformer Block 加工输入
理解词语之间的关系和上下文
        ↓
编码后的表示
包含输入句子的上下文信息
        ↓
Decoder 解码器
结合编码信息和已生成的内容
一步一步预测下一个词
        ↓
输出中文：
我 → 我喜欢 → 我喜欢苹果
```

**编码器内部在做什么？**

编码器会堆叠多个 Transformer Block。每个 Block 都会进一步加工输入表示。

以 `I love apples` 为例：

- Attention：让 `I`、`love`、`apples` 等位置结合上下文信息。
- FFN：进一步加工每个位置的特征。
- 残差连接和归一化：帮助信息传递与模型训练。

经过多层处理后，每个词的表示就包含了更多上下文信息。

**所以，编码器不是简单地把英文换成数字，而是逐层把输入变成更有上下文信息的表示。**



**解码器内部在做什么？**

Transformer 的解码器也有多个 Block，但与编码器有两个重要区别。

1. 生成当前词时，只能参考已经生成的词，不能偷看未来还没生成的词。（通过因果：生成喜欢的时候只能看到「我」，看不到「苹果」）
2. 解码器还会通过交叉注意力读取编码器提供的输入信息。（交叉注意力：解码器在生成答案时，主动去读取编码器对输入内容的理解）

#### 那为什么 ChatGPT 看起来没有编码器？

这是最容易混淆的地方：并不是所有 Transformer 都同时拥有编码器和解码器。

| 架构            | 组成            | 典型用途                  |
| --------------- | --------------- | ------------------------- |
| Encoder-only    | 只有编码器      | 理解、分类、语义表示      |
| Decoder-only    | 只有解码器      | 文本生成，例如 GPT 类模型 |
| Encoder–Decoder | 编码器 + 解码器 | 翻译、输入到输出的转换    |

GPT 类模型主要采用 Decoder-only 架构。它没有经典 Transformer 中独立的编码器，而是通过因果注意力处理已有文本，再预测下一个词。

## LLM 的自回归

自回归，就是模型根据已经生成的内容，接着预测下一个 Token，再把新生成的 Token 加进去，继续预测下一个。

LLM 生成文字时，通常不是一次性把整句话想好再吐出来，而是一步一步生成。

**用一个例子理解：**

假设你问模型：

“今天天气很……”

模型会这样生成：

```text
第 1 步：已有内容
今天天气很     预测下一个 Token  "好"
       ↓
第 2 步：更新内容
今天天气很好   再预测下一个 Token "，"
       ↓
第 3 步：继续生成
今天天气很好，适合……
```

**每生成一个 Token，模型就把它接到已有内容后面，再利用更新后的上下文预测下一个 Token，直到生成结束。**



**为什么叫“自回归”？**

把这个词拆开理解：

- 自：使用模型自己已经生成的内容。
- 回归：把之前的结果带回来，作为下一步预测的依据。

## 自监督学习的两种方案

1. 自编码：给模型一段内容，让它学会提取其中的重要信息，再尽可能还原出来。

   例如：把句子中的某些词遮住，让模型根据上下文猜出被遮住的词。

2. 自回归：给模型前半句话，让它预测后面最可能出现什么。

   例如：GPT通过大量文本学习下一个 Token 的概率分布，然后在生成时一步步预测后续内容。

## 为什么主流大模型都用 NTP 方案

为什么主流大模型都用预测下一个词 （Next Token Prediction，下一个 Token 预测）的方案：

训练目标简单、训练数据容易获得，而且学会预测下一个 Token 的过程中，模型能学到语言和世界的许多规律。

1. 不需要人工给每条数据打标签

   因为答案本来就在文本里：

   输入：苹果是一种常见的

   答案：水果

2. 一个简单任务，可以逼模型学习很多东西

   例如：

   > 牛顿提出了……

   模型可能需要知道牛顿与物理学的关系，才能较好地预测后续内容。

3. 训练效率高

   训练时：已知整段真实文本，可以并行计算多个位置的下一个 Token 预测。

   生成时：下一个 Token 尚未确定，通常需要先生成它，再继续生成后面的 Token。

4. 训练目标和实际使用方式天然一致

   GPT 最终要做什么？续写文本、回答问题、写代码、生成文章。

   这些任务都可以转化为：给定前面的内容，预测接下来应该生成什么。

## 指令微调

让一个已经学会“接着写文本”的大模型，进一步学会“听懂人的要求，并按照要求完成任务”。

核心就是：给模型看大量“指令 + 理想回答”的例子，让它学习怎样响应指令。

**预训练让模型学会预测文本，指令微调让模型更懂得按要求回答；而这两个阶段通常都可以使用 NTP 来训练。**

#### GPT做了哪些指令微调

**第一步：监督微调（SFT）**

给它看优秀的示范答案

问题：解释什么是自回归。

示范：自回归就是根据已有内容，逐步预测下一个 Token。

**第二步：学习人类偏好**

比较多个回答，判断哪个更好

回答 A：准确、清晰、符合要求。

回答 B：含糊、冗长、没有回答重点。

**第三步：进一步优化**

让模型更倾向于生成人类偏好的回答。

它主要是通过大量训练样本，调整模型参数，让模型更倾向于按照指令生成符合预期的回答。

把整个过程串起来就是：

- 预训练：学习语言、知识和规律。
- 指令微调：学习如何按照要求完成任务。
- 偏好优化与安全训练：进一步调整回答质量、行为偏好和安全边界。

#### 强化学习

指令微调是让模型学习优秀的示范答案；**强化学习则是让模型尝试生成答案，再根据奖励信号调整自己的行为。**

假设你问 GPT：

> 请用大白话解释什么是交叉注意力。

回答 A

交叉注意力是 Decoder 使用自己的 Query，去关注 Encoder 输出的 Key 和 Value，从而获取相关信息的机制。

回答 B

你可以把它理解成：解码器在生成答案时，去输入内容里寻找自己当前需要的信息。

假设用户更喜欢通俗易懂的回答 B。

奖励信号：模型会得到反馈，学习更倾向于生成符合用户要求的回答。

**注意：强化学习不是简单地把回答 B 复制进去，而是利用奖励信号更新模型参数，让类似的优质回答以后更容易出现。**

## 大模型的安全与合规

让大模型既能完成任务，又不泄露敏感信息、不轻易被攻击、不产生不可接受的风险，并且符合适用的法律法规。

- 安全（Safety & Security）：模型会不会造成伤害、被攻击、泄露数据，或者执行不该执行的操作。

- 合规（Compliance）：模型及其应用是否满足适用的法律、监管要求、行业规范和组织内部政策。

### 把它和 GPT 的训练过程串起来

- 预训练：让模型获得语言能力和知识，但也可能学到偏差或错误模式。
- 指令微调：让模型更好地遵循指令，并学习合适的响应方式。
- 强化学习与偏好优化：进一步调整模型的行为倾向。
- 安全工程：通过权限、过滤、隔离、校验和监控，保护真实应用。
- 合规治理：确保数据、产品和运营流程符合适用要求。

这几个环节相互配合，但没有任何一个环节能够单独保证绝对安全。

## LLM 的「涌现」到底是什么？

涌现（Emergence），指的是模型规模不断增大时，某些能力突然表现出来，或者在某个规模后明显变得更强，而小模型还表现不出来。

假设模型规模增加到某个阶段后，答对率从很低突然升高，人们就可能把这种现象称为「涌现」。

但要注意：模型的能力不一定真的在某一刻凭空出现。 它可能一直在逐渐进步，只是到了某个阶段，才足以在特定任务上表现出明显的成功。

**为什么模型变大，可能出现新能力？**

一个大语言模型经过预训练，会调整大量参数，学习文本中的规律。

模型规模增大，通常意味着可以使用更多参数、计算量和训练数据。这可能让模型学到更复杂的模式。

举个例子，模型要解决一道多步推理题，可能需要综合：

1. 理解题目中的条件。
2. 识别条件之间的关系。
3. 进行多步计算或推导。
4. 得出最终答案。

小模型可能只学会其中一部分；更大的模型可能学会足以完成整个任务的模式。

## LLM 上下文窗口

上下文窗口，就是大模型在一次处理过程中，能够纳入考虑的 Token 范围。

假设你让模型阅读一本很长的书，然后问它：

> 第 30 页提到的概念，和第 200 页的结论有什么关系？

如果相关内容都在模型当前能够处理的上下文范围内，它就有机会同时参考两处内容进行回答。

如果书太长，超过了上下文窗口，系统就可能需要截断部分内容、分段处理，或者通过 RAG 检索相关片段再交给模型。

**简单理解就是：对话中所有的内容，包括问与答。**

### 上下文不够怎么办？

1. **压缩上下文**（基本都是自动，也可以手动）：**有损**——摘要会掉细节，而且「模型以为自己记得、其实记串了」是最常见的坑
2. **分段 + 摘要接力**（每段算完生成摘要传给下一段），或 map-reduce。代价：跨段信息被切断，边界处最容易丢东西
3. **RAG 向量记忆**：通过 RAG 把对话都转成向量，存在在向量数据库中，然后按需召回

## LLM 是如何配合 RAG 工作的

LLM 负责理解问题、组织和生成答案；RAG 负责在回答之前，帮 LLM 找到相关的外部资料。

### 整体流程

假设你在公司问 AI：

> 我们公司的报销制度中，出差住宿每天最多能报销多少钱？

LLM 本身不一定知道你公司的内部制度。此时 RAG 就派上用场了。

```text
                                		① 用户提问

                                出差住宿每天最多报销多少钱？

                                         ↓

                                	② RAG 检索相关资料

                                在公司报销制度文档中寻找相关条款

                                         ↓

                                	③ 把检索结果交给 LLM

                                		问题 + 相关制度原文

                                         ↓

                                		④ LLM 生成回答

                             根据检索到的条款回答，并尽可能提供出处
```

### RAG 到底是怎么找到资料的？

第一步：准备知识库

收集 PDF、Word、网页、产品说明书、企业制度等资料。

第二步：切分文本（Chunking）

把长文档切成较小的片段，方便检索。例如把整本员工手册拆成多个主题段落。

第三步：建立索引

常见做法是用 Embedding 模型把文本转换成向量，再存入向量数据库；也可以同时建立关键词索引。

当用户提问时，系统会将问题用于检索，找出相关文本片段，再把这些片段交给 LLM。

```text
                                    		企业文档 / 知识库

                                           		 ↓

                                    	切分 + Embedding + 索引
                                    用户提问时，通过检索找到相关片段

                                             	 ↓

                                    Prompt = 用户问题 + 检索资料 + 指令

                                           		 ↓

                                    			LLM 生成答案
```

## LLM 多模态

多模态，就是让大模型不只处理文字，还能理解和处理图片、声音、视频等不同类型的信息。

### 多模态大模型到底是怎么工作的？

假设你向模型输入一张猫的照片。

**第一步：输入图片**

**第二步：把图片转换成模型能处理的表示。**

视觉编码器（Vision Encoder）或视觉处理模块，会从图片中提取形状、纹理、物体及空间关系等信息，并转换成向量或视觉 Token。

**第三步：与语言模型结合**

视觉信息和文字信息通过模型设计好的连接方式进入语言模型，使模型能够结合图片与问题进行推理。

**第四步：生成答案**

例如：“这是一只坐在沙发上的猫。

### 不同模态是如何处理的？

| 模态 | 模型主要处理什么                 | 举例               |
| ---- | -------------------------------- | ------------------ |
| 文本 | Token、语义和上下文              | 理解问题、写代码   |
| 图像 | 像素及视觉特征                   | 识别物体、理解图表 |
| 音频 | 声音信号及其特征                 | 语音识别、语音对话 |
| 视频 | 连续画面、时间信息，有时还有音频 | 总结视频、分析动作 |

不同模态的原始数据不同，但模型可以通过合适的编码和架构，把它们转化为能够被模型处理的表示。

例如：

- 文字可以被切分成文本 Token。
- 图片可以被转换成视觉 Token 或其他视觉表示。
- 音频可以转换成声学特征或音频 Token。
- 视频通常还需要处理连续帧及其时间关系。

### 多模态模型是怎么训练出来的？

可以粗略理解为三个阶段。

1. 模态内部的学习

   让模型学习图像中的物体、声音中的语音特征，或者文本中的语言规律。

2. 跨模态对齐

   通过图片与文字配对、音频与文本配对等数据，让模型学习不同模态之间的对应关系。

   例如，让模型学会照片里的狗与“狗”这个概念之间的关联。

3. 多模态指令微调

   让模型学习如何根据多模态输入完成具体任务，例如看图回答、语音对话、视频总结等。
